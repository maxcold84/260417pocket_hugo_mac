# Design Tokens

## Stack
- Tailwind CSS CDN is loaded from `hugo/themes/default/layouts/_default/baseof.html`.
- No build-time CSS pipeline or component library is used.
- Alpine.js controls stateful UI; HTML remains server-rendered or statically generated by Hugo.

## Colors
- Primary action: `bmw-blue` `#1C69D4`.
- Light surfaces: `white`, `gray-50`, `gray-100`.
- Light borders: `gray-200`, `gray-300`, `bmw-border` `#e5e7eb`.
- Dark page: `bmw-dark` `#111111`.
- Dark surfaces: `black`, `bmw-surface` `#1A1A1A`.
- Dark borders: `bmw-darkBorder` `#333333`.
- Status colors follow Tailwind defaults: green for success/published, red for destructive/error, gray for muted/hidden, orange for caution.

## Typography
- Base font stack: `"Helvetica Neue", Helvetica, Arial, sans-serif`.
- Navigation and action labels use small uppercase text with wide tracking.
- Product and section headings use light or medium weight rather than heavy display styling.
- Body copy uses `text-sm` to `text-base` with `leading-6` for readable dense commerce UI.

## Layout
- Main content width uses `max-w-7xl mx-auto px-4`.
- Product detail pages use a two-column desktop grid and single-column mobile stack.
- CMS pages use white panels with thin borders and compact controls for repeated admin work.
- Dynamic islands should stay inside the static Hugo layout and avoid page-level redesign.

## Components
- Primary buttons use `bg-bmw-blue hover:bg-blue-700 text-white`.
- Destructive actions use red text or red filled buttons after inline confirmation.
- Inputs use thin gray borders, `focus:ring-2`, and `focus:border-bmw-blue`.
- Cards/panels use small radii only when they frame repeated items or tools.
- Empty, loading, and error states should be explicit but compact.
- Product rating displays use inline SVG stars in Tailwind `text-orange-400/500` with compact numeric labels. Interactive rating inputs are 1-5 button groups with visible focus rings and stable inline dimensions.
- Product inquiry rows use thin bordered panels, compact status pills, and a left-accented BMW-blue answer block. Secret inquiries use gray/black lock badges and masked body copy; never expose private text in decorative previews.
- Product detail recommendation carousels use compact small-radius product cards in a horizontal scroll-snap rail, showing 2/3/4/5 cards per slide across mobile/tablet/desktop/wide layouts. Use BMW-blue active dots, focus rings, and SVG arrow/cart controls.

## Interaction
- Use inline confirmation UI instead of browser `confirm()` or `alert()`.
- Use `x-text` for user-provided text.
- Keep UI state on the Alpine component, not on fetched records.
- For dynamic data on static pages, prefer a small Alpine island that calls PocketBase routes.
- Autoplay interactions pause on hover or focus and must respect `prefers-reduced-motion`.

## Responsive
- Controls must stack cleanly at `375px`, use denser two-column or flex layouts from tablet width, and preserve table alternatives for CMS mobile views.
- Fixed-format elements such as action groups and counters should use stable min heights so loading and state changes do not shift nearby content.
